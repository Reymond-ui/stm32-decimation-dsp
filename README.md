
## Описание эксперимента

На микроконтроллер с ПК поступает зашумленный сигнал с частотой дискретизации 2000 Гц. Задача — понизить частоту до 250 Гц (коэффициент децимации M = 8) и сравнить два подхода:

*   **Тракт А (Прореживание):** Из каждого блока в 8 отсчетов берется только последний. Шум не подавляется, спектр алиасится в основную полосу.
*   **Тракт В (Усреднение):** Вычисляется среднее арифметическое 8 отсчетов (КИХ-фильтр с прямоугольным окном). Обеспечивает подавление широкополосного шума.
*   **Целочисленная арифметика:** Вся обработка в прошивке выполняется без использования плавающей точки (сдвиги и целочисленное сложение).

## Архитектура и протокол

*   **Микроконтроллер:** STM32F103C8T6 (тактирование HSI 8 МГц).
*   **Интерфейс:** USB-UART (115200 бод, 8N1).
*   **Частоты:** `Fs_in = 2000 Гц`, `Fs_out = 250 Гц`.

**Протокол обмена:**
*   **ПК → МК (10 байт):** `[0xAA, 0x55, S0, S1, ..., S7]` — заголовок и 8 беззнаковых отсчетов.
*   **МК → ПК (4 байта):** `[0xAA, 0x55, A, B]`
    *   `A = S[7]`
    *   `B = (S[0] + ... + S[7] + 4) >> 3` (сложение с 4 реализует округление к ближайшему).

## Структура проекта

*   `module1_simulation.py` — симуляция на Python. Спектральный анализ (FFT), расчет метрик (SNR, RMS) и визуализация временных диаграмм. Не требует подключения оборудования.

*   `module2_stm32_realtime.py` — скрипт для взаимодействия с МК. Отрисовывает графики в реальном времени и выполняет побайтовую сверку ответов МК с эталонной моделью на ПК.
*   `module2_mod.py` — расширенная версия с графическим интерфейсом и модулем аудиовоспроизведения.
*   *(Прошивка для STM32 реализована в виде конечного автомата, обрабатывающего байты заголовка и накапливающего пакет данных).*

## Запуск

1.  Установка зависимостей:
    ```bash
    pip install numpy scipy matplotlib pyserial sounddevice
    ```
2.  **Запуск симуляции:**
    ```bash
    python module1_simulation.py
    ```
    В консоль выводится теоретический и измеренный выигрыш по SNR, а также строятся графики спектров и временных рядов.
3.  **Работа с оборудованием:**
    После прошивки МК запустите:
    ```bash
    python module2_mod.py --port COM6
    ```
    *(Укажите актуальный COM-порт).*

## Математическое обоснование

Усреднение 8 отсчетов эквивалентно КИХ-фильтру с коэффициентами `h[k] = 1/8`. Его амплитудно-частотная характеристика (АЧХ) имеет нули на частотах, кратных 250 Гц (250, 500, 750, 1000 Гц). 

На частоте полезного сигнала (60 Гц) коэффициент передачи фильтра составляет `H(60) ≈ 0.909`, что дает ослабление на -0.83 дБ. Теоретический выигрыш от усреднения 8 независимых отсчетов составляет `10 * log10(8) ≈ 9.03 дБ`. С учетом ослабления сигнала АЧХ, реальный выигрыш по SNR составляет около `8.2 дБ`. В ходе симуляции и натурных испытаний получено значение ~8.0 дБ, что подтверждает корректность модели.

## Аудиовизуальный анализ

Поскольку выходная частота составляет 250 Гц, а полезный сигнал — 60 Гц, он находится в суббасовой области, которая не воспроизводится большинством стандартных динамиков ноутбуков. 

Для визуального и слухового сравнения в скрипт `module2_mod.py` введен параметр временного масштабирования (частотного сдвига). Аудиопоток ускоряется в 4 раза, что переносит сигнал 60 Гц в область 240 Гц. Данный сдвиг применяется исключительно к аудиотракту и не влияет на корректность работы протокола, метрики или графики. При прослушивании разница в уровне шума между Трактом А (прореживание) и Трактом В (усреднение) становится отчетливо различима.
